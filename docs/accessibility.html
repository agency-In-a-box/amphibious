Accessibility

Amphibious 2.0 is built with accessibility as a first-class concern. Every component includes ARIA attributes, keyboard navigation, and support for assistive technologies.

Overview

Amphibious 2.0 follows WCAG 2.1 AA guidelines across all 22 interactive components. The framework provides:

  • 32 prefers-reduced-motion rules for animation-sensitive users
  • 17 prefers-contrast rules for high-contrast mode
  • 60+ :focus-visible rules for keyboard focus indicators
  • Comprehensive ARIA attributes on every interactive component
  • Skip navigation link on all documentation pages
  • Semantic HTML as the foundation for all markup patterns
  • 418-line print stylesheet for print accessibility

ARIA Patterns

Each component implements the appropriate WAI-ARIA Authoring Practices pattern:

Modal Dialog

<div role="dialog" aria-modal="true" aria-labelledby="modal-title">
  <h2 id="modal-title">Dialog Title</h2>
  <button aria-label="Close modal">&times;</button>
</div>

Tab Panel

<div role="tablist" aria-label="Content tabs">
  <button role="tab" aria-selected="true" aria-controls="panel-1">Tab 1</button>
  <button role="tab" aria-selected="false" tabindex="-1">Tab 2</button>
</div>
<div role="tabpanel" aria-labelledby="tab-1">Content</div>

Accordion

<button aria-expanded="true" aria-controls="panel-1">Section Title</button>
<div id="panel-1" role="region" aria-labelledby="header-1">Content</div>

Navigation

<nav aria-label="Main navigation">
  <button aria-expanded="false" aria-controls="nav-menu">Menu</button>
  <ul id="nav-menu" role="menubar">
    <li role="none"><a role="menuitem">Link</a></li>
  </ul>
</nav>

Toast Notifications

<div role="region" aria-live="polite" aria-label="Notifications">
  <div role="alert" tabindex="-1">
    <p>Operation completed.</p>
    <button aria-label="Close notification">&times;</button>
  </div>
</div>

Breadcrumb

<nav aria-label="Breadcrumb">
  <ol>
    <li><a href="/">Home</a></li>
    <li aria-current="page">Current Page</li>
  </ol>
</nav>

Form Validation

<label for="email">Email</label>
<input id="email" type="email" aria-required="true"
       aria-invalid="true" aria-describedby="email-error" />
<span id="email-error" role="alert">Please enter a valid email.</span>

Reduced Motion

All animations and transitions respect the prefers-reduced-motion media query. When a user has enabled reduced motion in their OS settings, Amphibious will:

  • Disable CSS transitions and animations
  • Set carousel slide transition speed to 0ms
  • Remove parallax and scroll-based effects
  • Keep opacity changes (non-motion) for visibility feedback
/* Applied across 32 rules in the framework */
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation-duration: 0.01ms !important;
    transition-duration: 0.01ms !important;
    scroll-behavior: auto !important;
  }
}

High Contrast

Amphibious includes 17 prefers-contrast: high rules that enhance visibility when users enable high-contrast mode:

  • Borders become more prominent on interactive elements
  • Focus indicators use thicker outlines
  • Subtle background differences are amplified
  • Text contrast is maximized against backgrounds

All text colors meet WCAG AA contrast requirements (4.5:1 for normal text, 3:1 for large text). The muted text color --color-muted uses #767676 which achieves exactly 4.54:1 contrast ratio.

Dark Mode

The dark mode system is accessibility-aware:

  • System preference: Automatically follows prefers-color-scheme
  • Manual override: Toggle button with clear sun/moon icons
  • Persistence: User preference saved in localStorage
  • Keyboard shortcut: Cmd/Ctrl+Shift+D
  • Screen reader: Toggle announces current mode via aria-label
  • Smooth transition: 200ms crossfade to prevent jarring switches
  • Meta theme-color: Updates <meta name="theme-color"> for mobile browser chrome

Form Accessibility

The form validation system provides comprehensive screen reader support:

  • Every input is linked to its label via for/id pairing
  • Error messages are linked via aria-describedby
  • Invalid fields are marked with aria-invalid="true"
  • Required fields use aria-required="true"
  • Error messages use role="alert" for live announcements
  • First invalid field receives focus on failed submission
  • Character counters announce remaining characters

Focus Management

Focus is carefully managed across all interactive components:

Focus Trapping

Modal dialogs and mobile navigation menus trap focus within their boundaries using a shared trapFocus() utility. Tab and Shift+Tab cycle through focusable elements without escaping to the background content.

Focus Restoration

When modals close, focus returns to the element that triggered the modal opening. This ensures keyboard users don't lose their place in the document.

Focus Indicators

All interactive elements use :focus-visible for keyboard-only focus rings, avoiding visual clutter for mouse users while maintaining clear indicators for keyboard navigation. The default focus style uses a 2px offset ring in the primary brand color.

Skip Navigation

All pages include a skip link as the first focusable element:

<a href="#main-content" class="aiab-skip-link">Skip to main content</a>

Testing

Amphibious validates accessibility through multiple layers:

Automated Testing (CI)

  • axe-core: 8 component patterns validated against axe-core rules in CI
  • Manual ARIA checks: 7 additional tests verify ARIA linkage patterns
  • 15 total a11y tests running on every push and pull request

What We Test

  • Modal: role="dialog", aria-modal, aria-labelledby
  • Tabs: role="tablist"/tab/tabpanel linkage
  • Navigation: aria-label, aria-expanded
  • Toast: aria-live="polite", role="alert"
  • Forms: label association, aria-describedby, aria-invalid
  • Breadcrumb: aria-current="page"
  • Accordion: aria-expanded, aria-controls
  • All buttons: accessible name verification

Manual Testing Checklist

In addition to automated tests, we recommend testing with:

  • VoiceOver (macOS) or NVDA/JAWS (Windows)
  • Keyboard-only navigation (unplug mouse)
  • Browser zoom at 200% and 400%
  • High-contrast mode in OS settings
  • Reduced motion in OS settings
